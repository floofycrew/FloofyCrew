# floofy-core

The shared core of FloofyCrew, published as-is to both editions: the `floofy.json`
manifest schema and validator, the dependency resolver, the Patcher engine, the
registry client and signature verification, the compatibility-matrix format, the
Loader app runtime and the SPA host. Everything here is stdlib-only Python 3.12
(plus ES modules for the dashboard side) and must run unchanged on the host's own
interpreter. It must not contain any edition-specific value — no internal
hostnames, package names, account identifiers or people — those belong in
`editions/*`; CI enforces this with `scripts/check_no_internal_identifiers.py`.
Tests live in `tests/`.

## Layout

| Module | Purpose |
|---|---|
| `floofy_core.schema` | the five JSON Schemas (`floofy.schema.json`, `patch.schema.json`, `index.schema.json`, `compat.schema.json`, `signature.schema.json`), `load_schema()`, and `schema/check.py`, a small stdlib JSON Schema checker; field reference in `schema/README.md` |
| `floofy_core.canonical` | `canonical_bytes(obj)` — the `json-c14n-1` form (sorted keys, no whitespace, UTF-8) a detached registry signature is computed over; re-derived from the *parsed* document so the served file's whitespace never matters |
| `floofy_core.sigverify` | pure-Python Ed25519 verification (RFC 8032, pinned by the §7.1 vectors): `ed25519_verify()`, `key_id(public)` = `sha256(public)[:16]`, `parse_signature_document()` for the `.sig` JSON (`{schema, alg: ed25519, keyId, signature, signedAt, canonical}`), `verify_detached(payload, sig, allowed_keys, expected_key_id=)` → `VerifyResult(status verified\|invalid\|unsigned, detail, key_id)`; never raises on hostile input |
| `floofy_core.signing` | the signer's side, same curve code: `generate_keypair()`, `KeyPair.save_private()` (mode 0600) / `save_public()`, `load_private_key()`, `load_public_key_record()`, `sign_detached()` / `sign_document()`; `python -m floofy_core.signing keygen\|sign\|key-id`. Private keys never enter a repository |
| `floofy_core.semver` | `Version` (SemVer 2.0), `HostVersion` (the shapes KiroCrew prints, with the `X.Y.Z` `base`), `Range` (npm-style ranges) |
| `floofy_core.validator` | `validate_mod()` → `ValidationReport` of `Finding`s: schema, hashes, parts, targets, network |
| `floofy_core.resolver` | `resolve(records, host)` → `Resolution`: graded dependencies, mutual conflicts, load order, cycle → `Conflict`, `strict` → `Unsupported`, typed `Reason` enum; governance is never a reason |
| `floofy_core.archive` | `open_archive_safely()`: listing checked before extraction (no symlinks, absolute paths or `..`) |
| `floofy_core.targets` | `TargetPolicy`: engineering-rule targets (error) vs governance files (warning, accepted per file); adapters extend it |
| `floofy_core.netscan` | plaintext / undeclared-host scan and `host_matches()` shared with the Loader's `ctx.http` |
| `floofy_core.cli_validate` | `floofy validate` front end (`--json`, exit 1 on errors only) |
| `floofy_core.payloads` | `Payload`, `PayloadProvider`, `discover_payloads()` → `DiscoveryResult` (every searched root listed on a miss); the layout-agnostic `find_package_dirs()` walk, `read_host_version()` (`__version__` + the `BUILD_VERSION` stamp, the host's rule), `channel_for_version()`; generic `FindSpecProvider` / `ExtraRootProvider`; edition adapters add their own providers |
| `floofy_core.deploy` | `DeployManifest` (`deploy/<payload>.json`, atomic save, `record_patch/added/sidelined`), `Backups` (first-write-only `.floofybak` sidecars, `restore_file`, `refresh` for host-updated drift), `added_name()` / `is_floofy_added()` (`-floofy` marker), `classify_drift()` → `DriftReport` with the Requirement 5.3 decision table and default actions |
| `floofy_core.patches` | `PatchDescriptor.load()` (schema-validated; `mode` in-place \| import-map, optional `find` literal, glob chunk targets, per-op `occurrence` only \| first \| last, in-memory `UiAsset`s), `apply_descriptor()` → `PatchResult` with per-op atomicity and typed `Skip`s (`NotApplicable`, `AlreadyApplied`, `FingerprintMiss`, `FingerprintAmbiguous`), `fingerprint_report()` (the reporter), `merge_import_map()` / `drop_modulepreload()` for the spike-1.4 remap path |
| `floofy_core.spa_patches` | the spike-1.4 module-patching path (task 5.3): `resolve_chunk_target()` (a glob on the hashed name → exactly one file), `apply_import_map_patch()` (ops on the ORIGINAL chunk text, `rebase_imports()`, marker comment, patched copy + `.floofy.json` sidecar under the Loader app's `ui/patched/`, import-map key and dropped `modulepreload` in `index.html`), `is_entry_chunk()` (the `<script src>` chunk falls back to the alias graph), `refresh_patched_index()` (`ui/patched/index.json` for the runtime `window.floofy.patches`), `default_ui_root()` |
| `floofy_core.boot_script` | the generated `index.html` descriptor (task 5.4, Requirement 4.3): `build_boot_descriptor(boot_mods, host_home=…)` → the spike-1.3 **loader tag** (`insert-before` the `main-*.js` module tag) + ONE inline `<script id="floofy-boot">` rendered from the `spa-host/src/boot.mjs` template with every `activation: boot` part's config in load order (`insert-before` the first `<script`, `occurrence: first`) + one `<style id="floofy-boot-css-<id>">` per mod (`append-head`); `read_theme_defaults()` (the host config's `dashboard.theme_color` / `theme_mode`, the cold-client fallback); favicon/logo files become `UiAsset`s copied under `ui/boot/<id>/`; refuses `</script`, `</style` and oversized parts |
| `floofy_core.aliasgraph` | `build_graph()` → `ChunkGraph` (importer graph of `assets/` by hashed-name reference), `closure()`, `republish()` (aliases `<stem>-<runtag>-floofy.<ext>` with rebased references, stale-alias removal, repointed `index.html` text returned to the caller), `sideline_sidecars()` (`.br`/`.gz` → backup names, reversible); the fallback for targets the import-map remap cannot reach |
| `floofy_core.patcher` | `Patcher(data_home, payloads, ui_root=…)`: `apply(patch_set)` (revert-then-patch every payload, drift actions, target policy, import-map copies under `ui/patched/`, alias graph, `audit.jsonl`), `restore()` (manifest + glob sweep; a restore of every payload also sweeps `ui/patched/`, a partial one keeps copies other payloads still map to), `status()`, `verify()` over the dashboard socket/loopback (`verified` / `dormant` / `failed` / `no-gateway`; patched copies checked through the app-UI route), `gc()` (vanished payloads and orphaned `ui/patched/` copies); `PlannedPatch`, `resolve_target()`, `url_for()` |
| `floofy_core.gateway` | `GatewayEndpoint` (unix socket `dashboard-<port>.sock` or loopback port, `GET`/`request()` with identity encoding), `find_endpoints(host_home)`, `probe_version()` / `served_version()` from `/api/health` — the host discloses `version` only to a direct-local loopback **TCP** peer with a served `Host`, so a bare answer over the socket is retried once over `127.0.0.1:<port>` (port from the socket name; `dashboard-0.sock` has none) while every other call stays on the socket; `GatewaySession` / `session_for()` — the manager's authenticated loopback calls (a session token minted on `/api/token/local` with the host's local secret `run/gateway-<port>.secret` / `.local_secret`, then the `mc_token_<port>` cookie) |
| `floofy_core.consent` | the one-time consent record (Requirement 11.1): `WARNING_TEXT`, `WARNING_VERSION`, `ACCEPT_PHRASE`, `read_consent()` / `write_consent(how=typed\|flag)`, `consent_reference()` → `{warningVersion, sha256}` of `consent.json` (the `consentRef` audit rows carry) or `None`; `floofy_loader.consent` re-exports it |
| `floofy_core.datahome` | `DataHome` — the `<host home>/floofy/` layout used by the CLI, the Loader (`floofy_loader.paths.FloofyPaths` is this class) and the Forge, incl. `registries.json`, `profiles/`, `quarantine/<ver>/`, `host-state.json`, `hostchange-<ver>.json`, the `vanilla-once` marker |
| `floofy_core.audit` | `AuditLog(data_home, actor=…)` — the **one** `audit.jsonl` writer (Requirement 11.5) behind every surface: the CLI commands, the seam kind handlers, the Patcher, the Loader's `net-denied` rows and the manager UI's in-process route (`actor: ui`); `record(op, **fields)` appends `{ts, op, actor, by, consentRef, mod, version, payload, files[], governanceFlags[], result, detail, …op-specific}` with `consentRef = {warningVersion, sha256}` of `consent.json` or `null`, never raising into the operation; `read_audit(path, tail=, ops=)` backs `floofy audit` |
| `floofy_core.compat` | `CompatCache` / `CompatRow` — the `cache/compat.json` reader (Requirement 9.2) shared by the Loader boot, `doctor`, `update` and the host-change handler |
| `floofy_core.modstore` | `installed_mods()` → `InstalledMod` records from `mods/*/floofy.json`, `read_enabled()` / `write_enabled()`, `CODE_KINDS` (`python-hook`/`spa` land disabled), the `mods/<id>/.floofy/source.json` install record |
| `floofy_core.hostcli` | the host's own CLI driven by the manager: `find_launcher()` (`--kirocrew`, `PATH`, the payload's `bin/kirocrew`), `run_host_cli()` with `KIROCREW_HOME` pinned, `config_set_many()` with `kirocrew config set` semantics (`_parse_value`, `_dict_set_create`, the `<config.json>.lock` flock RMW), `grant_app_trust()` — the operator-writable `agent.apps_trusted` grant (Requirement 2.3) |
| `floofy_core.loaderapp` | the installed Loader app as the manager sees it: `installed_meta()` (`apps/floofycrew/installed.json`), `obtain_build()` (`--loader-app` dir/archive, else a build from the checkout), `early_install_module()` (the shim installer executed from the installed app by file path through `load_module_from_file()`, registered in `sys.modules` before it runs — its dataclasses need that; task 10.9) |
| `floofy_core.selfupdate` | FloofyCrew's own update check and self-update (Requirement 7.7, 11.6; task 10.7): `ReleaseFeed` (adapter-provided: `github-releases` — the GitHub releases API, the release body being the build's `RELEASE.md` — or `release-notes` — a raw `RELEASE.md` on a package branch, artifacts as blobs at the tag), `parse_release_notes()` / `parse_sums()`, `fetch_release()` → `Release{version, tag, supports, url, sha256s, assets}`, `check()` — the daily cached check (`cache/self-update.json`, 24 h, `--offline`, `updates.check`, failures cached as `unreachable`, never blocking) → `UpdateCheck` with the notice rule `notice_text()` (newer **and** `supports[edition][channel]` names the running host), and the staged swap: `download_release()` (every artifact verified against `SHA256SUMS`, the notes' table must agree), `swap()` (`<target>.new` → `os.replace`), `write_stage()` / `read_stage()` (the Loader archive under `pending/self-update/`). HTTPS only (loopback plaintext for tests), a generic agent, nothing identifying in the request |
| `floofy_core.settings` | FloofyCrew's own settings `config.json` (`floofy config get|set`): `Settings` with typed, defaulted, allowlisted keys — today `updates.check` (bool, `true`) |
| `floofy_core.triggers` | re-apply triggers (Requirement 6.1): `systemd_units()` / `launchd_plist()` / `path_wrapper_script()` generators, `UserTimerTrigger` (systemd user timer at :55 on Linux, launchd agent on macOS), `PathWrapperTrigger` (public venv installs), `loader_startup_status()`, the `TriggerManager` protocol and `trigger_managers()` collecting the adapters' `triggers()` |
| `floofy_core.installer` | the install engine (Requirement 7.6, 11.4, 11.7): `resolve_source()` (path / archive / https URL — plaintext only to loopback — / registry `id[@version]` with the index's sha256 checked), `disclose()` → `Disclosure` (parts with seam and payload impact, declared hosts, validator flags, governance-altering targets, the host's verdicts as warnings), `place()` into `pending/<id>/` or `mods/<id>/` keeping `.floofy/`, `run_handlers()` over the kind handlers |
| `floofy_core.kinds` | one handler per part kind (`KindHandler`: `install`/`uninstall`/`status` → `PartOutcome` with seam, `modifiesPayload`, governance warnings; Requirement 2, 2.7): `theme`, `dropins` (agent/skill/appearance), `config`, `app`, plus the Loader-managed (`python-hook`, `spa`) and Patcher-managed (`patch`) handlers |
| `floofy_core.registry` | the merged registry cache reader `IndexCache` (`cache/index.json`, one document per usable source: `{"schema": 1, "merged": true, "documents": [{source, key, url, trust, signature, document}]}`, or a single index document): `search()`, `best_version(ref, base_version=, edition=, host_version=, channel=, compat=)` → `BestVersion` = the newest version known to work on this host (Requirement 9.2: graded by the matrix row for `edition × channel × hostVersion`, else the index's inline `compat` cell; `tested` > `expected` > unknown; `broken` and `yanked` excluded, out-of-range excluded, the reason names what was excluded), `pick()` (an exact requested version, else `best_version`), `by_hash()` (Requirement 8.5), `find()` by key then bare id; a mod id present in two sources is namespaced `<label>/<id>` (Requirement 8.4), the label being the user's configured source name (else its cache key), never the index's own `source` claim |
| `floofy_core.registry_sources` | registry sources and per-source trust (Requirement 8.3, 8.4, 11.3, 11.6): `registries.json` `{schema, sources[{url, name, trust index\|owner, allowUnsigned, keyId, publicKey?, hostRegistry?, addedAt}]}` via `Source` / `SourceStore` (`add()` refuses plaintext non-loopback URLs, derives `keyId` from a pinned `publicKey`, and reports a loosening; `remove()`, `find()` by url\|key\|name; `Source.file_url()` fills a `{file}` placeholder for hosts whose raw view needs a query string; `Source.from_default()` for an adapter's shipped row), `refresh(opener_for=)` (HTTPS only — plaintext only to loopback — into `cache/sources/<key>/` with a `meta.json` verdict, an adapter-supplied opener per URL for network identity, a `rollback` flag when a verified index is older than the cached one, `RefreshOutcome.decisions()` for the audit row), `is_usable(status, source)` = verified, or any fetched index the user allowed unsigned (applied at refresh **and** by `rebuild_merged()` so tightening/loosening needs no refetch; a source's `compat.json` rows are merged under the same rule applied to *its* signature), `rebuild_merged()` of `cache/index.json` / `cache/compat.json`; `verify_index()` / `VERIFIER` = the real detached-signature check: `sigverify.verify_detached` over the canonical JSON with `trusted_keys_for(source)` = the edition-pinned keys (`KEY_PROVIDER`, default `editions.registry_keys()`) plus the source's own pinned key, `source.key_id` restricting to one key → `verified` / `invalid` / `unsigned` |
| `floofy_core.hostchange` | host-version-change handling (Requirement 6.2, 6.3): `HostState` (`host-state.json`), `detect_change()`, `handle_host_change()` = reporter (offline bundle fingerprints) + `anchors` + compat row + re-apply + `decide_yeets()` (strict range excluded / matrix `broken` / fingerprint miss / Loader request) + `yeet()` into `quarantine/<last-working-version>/<id>/` with `enabled.json` preserved and seam parts uninstalled + `hostchange-<ver>.json`; `restore_quarantine()` (automatic on rollback, `floofy yeet --restore`); `apply_if_changed()` is the triggers' and the Loader's entry |
| `floofy_core.anchors` | `anchors.json` (the host names the Loader, manager and mods rely on) and `check_anchors(payload)`: `ast`-based presence check against a payload's sources without importing it → `pythonAnchors {matched, total, missed[]}` (Requirement 9.1) |
| `floofy_core.profiles` | profiles (Requirement 7.5): `Profile` lockfile `profiles/<name>.lock.json` (`{schema, name, savedAt, hostVersion, edition, floofycrew, mods{id: {version, enabled, source, sha256}}}`), `snapshot()`, `plan_use()` (set-flag / install / reinstall / disable-extra), export/import as one file |
| `floofy_core.scaffold` | `floofy new <kind>`: schema-valid skeleton per kind + README, MIT stub, `tests/smoke_test.py`, GitHub Actions workflow; `refresh_files()` rehashes `files[]` (Requirement 14.1) |
| `floofy_core.cli` | the `floofy` command (task 6.x): `main.py` (parser, `main()`, the in-process `run()` the manager UI calls), `context.py` (`CliContext`: homes, lazily discovered payloads, governance, gateway session, audit, `registry_target()` = the host facts + cached matrix every registry grading uses, `url_opener()` = the edition adapter's network identity per URL), `console.py` (confirmations; typed answers never satisfied by `--yes`), one `cmd_*.py` per concern — `cmd_init` (`init`, `deinit`), `cmd_doctor` (`doctor`, `status`, `vanilla`), `cmd_mods` (`install`, `uninstall`, `enable`, `disable`, `update`, `search`, `dev`; `search`/`install <id>`/`update` grade candidates with `IndexCache.best_version` against the matrix row for this host — Requirement 9.2), `cmd_patch` (`apply`, `restore`, `verify`, `validate`), `cmd_yeet` (`yeet`, `hold`), `cmd_profile` (`profile save\|use\|list\|export\|import`), `cmd_scaffold` (`new`), `cmd_registry` (`registry add [--trust index\|owner] [--allow-unsigned] [--key-id] [--name] [--no-refresh]` — the loosening warned and audited as `registry-trust-loosened` — `remove`, `list`, `refresh [SOURCE]`, `defaults` (the edition's shipped source, verified against its pinned keys, plus its host App Store row), `host-registry [--apply]` (show / re-add the host App Store rows); `--public-key` pins a third-party source's Ed25519 key, `--key-id` restricts it to one key, `--host-registry REPO[@BRANCH] [--host-registry-name ID]` adds the source's git repository as an operator row of the host's federated app registries (confirmed, audited as `host-registry-add`; Requirement 8.6); `audit [--tail N] [--op OP]`; `which <sha256>`) |
| `floofy_core.editions` | adapter discovery by module prefix `floofy_edition_*`: `edition_providers()`, `combined_edition_probe()`, `governance_locations()`, and the registry hooks `registry_keys()` (the union of the adapters' pinned Ed25519 public keys), `default_sources()` (the shipped source rows, tagged with the adapter's edition), `registry_opener(url)` (an adapter's network identity for a URL — the internal SSO cookie jar — else anonymous), `pinned_registry_ids()` (host app-registry ids the manager must never reuse) |
| `floofy_core.hostregistry` | the host's federated app registries (Requirement 8.6): `HostRegistryRow(name, repo, branch)` validated with the host's own rules (`routes.py` L2964 repo charset, L3922 name, L3925 branch, pinned-id/repo refusal L3907–L3954), `current_rows()` / `apply_row()` / `remove_row()` through `GET`/`PUT /api/apps/registries` on the authenticated loopback session when a gateway runs, else the same edit of `config.json` `registries[]` under the host's lock; always an operator row (`trust: index`) under FloofyCrew's own id, never an id the edition pins (`editions.pinned_registry_ids()`) |
| `floofy_core.governance` | `GovernanceSnapshot.read(locations)` (policy tiers, `config.json` app gate, admission files, `/api/status`), `warnings_for()` / `survival_check()` → `GovernanceWarning`s (codes in `WARNING_CODES`; warnings, never gates — DR-5), the `Confirmer` protocol (`AlwaysConfirm`, `NeverConfirm`, `CallableConfirmer`) the Patcher asks for Requirement 5.9 |
| `floofy_core.themes` | the host's theme-pack validator ported (`validate_theme_dir()`, levels 0–2, caps, denylists, colour allowlist) and `direct_write_theme()` — the byte-equivalent stage-validate-rename install used when `theme_install` is closed (Requirement 2.1, 2.8) |
| `floofy_core.cli_patch` | `floofy-patch apply\|restore\|status\|verify\|gc` (`--root`, `--payload`, `--no-adapters`, `--port`, `--json`, `--confirm-governance`); `FLOOFY_NO_ADAPTERS=1` limits discovery to `--root` (set by the test session) |
| `floofy_core.spa_report` | the SPA reporter from Python (Requirement 4.5, 9.1): `load_registry()` (`spa-host/src/surfaces.json`, or `ui/surfaces.json` beside a vendored core), `check_bundle_fingerprints(dist_dir)` — the **offline** check of the `bundle` fingerprints against a `static/dist` on disk (stems discovered from the shell and `./<stem>-<hash>.js` references, never by hash), `run_browser_report(url, token)` — the **live** `window.floofy.report()` through headless Chromium (Playwright imported inside; injects the host module tag when `index.html` carries none); both return `SpaReport` with the matrix block `spaFingerprints {matched, total, missed[]}` |
| `floofy_core.cli_spa` | `floofy-spa verify --spa --url\|--port\|--ready-file [--token] [--extra-surfaces] [--screenshot] [--json]` (exit 1 when anything is missed; the `floofy verify --spa` front end for 6.x) and `floofy-spa bundle-check --dist DIR` (offline, no browser) |

`examples/<kind>/` holds one minimal valid mod per part kind; keep their hashes
current with `python scripts/hash_example_files.py` (`--check` in CI).

`tests/fixtures/dist-<ver>/` are trimmed real dists from three host versions
(see `tests/fixtures/README.md`; regenerate with `scripts/make_fixture_payload.py`).

Tests never touch a live host install: `tests/floofy_testing.py` sets
`FLOOFY_NO_ADAPTERS=1` and a scratch `KIRO_HOME` for the session (the agent seam
lands in `KIRO_HOME`, which `--home` does not move), and every conftest
fingerprints the live dashboard shells and the live drop-in seams' `.floofy-owner`
sidecars before and after the run. The opt-in real-gateway smoke
(`tests/test_real_gateway.py`, `FLOOFY_REAL_PAYLOAD=1`) runs a copy of a payload
under `.scratch/` with scratch homes; see its docstring. `pytest -m registry`
runs the registry and compatibility-matrix suite alone (task 7.6; ~20 s):
`tests/test_registry_signing.py` is its index — RFC 8032 vectors and the openssl
cross-check, sign/verify/tamper, pinned keys, schemas, `best_version` grading,
hash lookup, collision namespacing, download checks — with the end-to-end CLI
trust chain in `tests/test_cli_registry_audit.py`, the tooling in
`registry-tools/tests/`, the adapters' pinned keys in `editions/*/tests/` and the
host-side acceptance (`app-registry.json` read by the host's own reader, the
operator row's `PUT` round trip) in `registry-tools/tests/test_app_registry.py`
and `loader-app/tests/test_gateway.py`.
